# UI 页面制作与接入流程

[文档导航](../../README.md) · [框架模块](../README.md)

新增或改版先完成需求和复用调查；已明确目标的局部修复可直接进入所需步骤。[UI 职责与生命周期](README.md)、[复用目录](ReuseCatalog.md)、[Prefab 规范](PrefabRules.md)、[验收](Validation.md)。这些分析步骤由人或 Agent 执行，UI Panel Manager 不会自动完成效果图分析。

## 1. 从需求和效果图到制作方案

### 1.1 先明确任务与交付范围

例如用户说“添加一个结算页面”时，先记录已有信息：所属游戏/活动、打开时机、效果图、指定的现有页面、希望完成的范围。区分仅做视觉 Prefab、接入现有业务、以及新增业务能力；没有说明的部分标为待确认，不自动把视觉制作扩大成奖励、广告或结算系统开发。

“添加结算页”不必然表示新增一个 UIForm，也可能表示改版已有结算页。用户没有确定时，先做只读调查和效果图分析，再带着具体候选确认；用户已经明确“修改 X”或“新增独立页面”时沿用该决定，不重复询问。

效果图缺失时可以先调查已有页面、提出结构草案，但不能声称已按图拆解或完成视觉还原。图片上不能看出的交互和数据规则不能当作既定需求。

### 1.2 分析效果图和页面状态

分析输出以一份简短结构表和必要的层级草图为主，优先在当前对话展示。只有用户需要留档或多人交接时，才为本页面增加专用说明文件。

| 分析项 | 要明确什么 |
| --- | --- |
| 页面形态 | 全屏、弹窗、覆盖层或嵌入区；哪些区域固定、哪些随内容伸缩 |
| 区域拆分 | 背景/遮挡、标题、统计信息、奖励区、列表、操作区、关闭入口 |
| 数据与数量 | 静态文案还是运行时数据；重复项数量是否可变；空/单项/多项时如何显示 |
| 滚动 | 哪个区域滚动、方向、可见范围；标题和按钮是否固定；内容不足一屏时如何处理 |
| 交互 | 按钮动作、点击空白关闭、返回键、点击穿透、重复点击、点击物品是否弹提示 |
| 状态 | 正常、空数据、加载、失败、不可领取、已领取等本次业务实际需要的状态 |
| 适配 | 图的尺寸/比例、目标屏幕比例、安全区、长文本和多语言换行 |
| 表现与素材 | 图片、九宫格、字体、图标、动画；已有素材、缺失素材及允许的占位范围 |

每个关键结论注明来源：**图上可见 / 现有实现确认 / 制作建议 / 待用户确认**。例如“图中显示三项奖励”是观察，“奖励永远只有三项”不能由这一张图推出。

不把整张效果图作为最终可交互页面的背景，也不默认已有可用的分层素材。缺少会影响还原的素材时列出具体项，确认补充或占位方案；可以继续推进不依赖这些素材的结构工作。

### 1.3 调查现有页面和可复用元素

只调查目标页面、同类页面及其直接依赖。优先检查项目当前代码、Prefab 结构、序列化字段、引用方和 UIForm 表；文件名相似只能作为候选，不能作为兼容结论。

调查分成三个层次：

| 层次 | 判断内容 | 输出 |
| --- | --- | --- |
| 整页 | 业务目的、参数、打开入口和生命周期是否一致；改动是否影响其他游戏/活动 | 修改现有页是否合适，以及受影响的调用方 |
| 页面骨架 | 根布局、遮挡、标题/内容/按钮区域、开关动画是否适用 | 使用哪一个模板；是否需要保留或调整局部结构 |
| 子元素 | 奖励格子、排行榜行、统计行、按钮、头像、提示框的显示与交互是否匹配 | 直接复用、参数配置、局部扩展、另建或暂不拆分 |

检查复用对象的资源归属。新页面可以独立注册并复用公共 Widget；复用 Widget 不等于修改它的源 Prefab。改公共源 Prefab 会影响所有引用者，要列出影响，不能只看当前页面。

确认复用前同时检查脚本与资源：公开绑定方法、必要字段、尺寸约束、动画目标、数据依赖、池化支持和退出清理。只做过源码检查时明确“候选，尚未验证视觉/运行”，实际制作阶段再在 Unity 中读回和验证。

当前结算相关候选如下，仅供调查入口，不是默认选择：

| 候选 | 当前可确认的用途与限制 |
| --- | --- |
| [GameOverUIPanel](../../../../GameMain/Scripts/UI/Panel/GameOverUIPanel.cs) / [Prefab](../../../../GameMain/UI/UIPanel/GameOverUIPanel.prefab) | 使用 ProcedureGame 参数，含下一关、宝箱和关闭时广告判断；不能当作纯视觉模板复制 |
| [SettlementRankUIPanel](../../../../GameMain/Scripts/UI/Panel/SettlementRankUIPanel.cs) / [Prefab](../../../../GameMain/UI/UIPanel/SettlementRankUIPanel.prefab) | 带 ScrollRect、排行榜数据、虚拟列表和结算表现；适用于调查排行区域，不能假定适用于所有结算页 |
| [ClaimRewardsUIPanel](../../../../GameMain/Scripts/UI/Panel/ClaimRewardsUIPanel.cs) / [Prefab](../../../../GameMain/UI/UIPanel/ClaimRewardsUIPanel.prefab) | 使用奖励/宝箱参数，含领取相关行为；复用前明确谁实际发奖 |
| [RewardItemView](../../../../GameMain/UI/UIPrefabs/Reward/RewardItemView.prefab)、[RewardSlotView](../../../../GameMain/UI/UIPrefabs/Reward/RewardSlotView.prefab) | 奖励展示候选；是否直接复用需核对图中尺寸、样式及绑定契约 |

| [UIPanel_Template](../../../../GameMain/UI/Template/UIPanel_Template.prefab)、[PopupUIPanel_Template](../../../../GameMain/UI/Template/PopupUIPanel_Template.prefab) | 页面骨架候选；当前 UI Panel Manager 固定复制前者，不会自动按效果图选择弹窗模板 |

### 1.4 判断滚动与 Prefab 拆分

**滚动根据内容规模和布局决定。** 图片出现裁切、滚动条或连续列表可作为线索，但截图不能证明最大数据量。先确认内容上限及可见区域，再选方案：

- 内容固定且目标比例下能容纳：普通布局。
- 内容数量/高度可变并可能溢出：明确局部 ScrollRect 区域，固定标题/按钮放在滚动区外。
- 大量重复项：评估现有列表复用/虚拟化能力；不用一个固定条数阈值代替实际布局和性能判断，也不为少量项默认引入虚拟列表。
- 多个滚动区域或嵌套滚动：仅在交互确实需要时使用，写清拖拽归属与方向。

同时约定首次打开定位顶部/当前项、重新打开是否保留位置、数据刷新是否改变位置。ScrollRect、对象池和虚拟化是不同能力，不能因一个奖励格子是 Prefab 就认定它可以直接进入现有 Item 池。

**Prefab 拆分以重复、独立行为或已知复用需求为依据。**

| 元素 | 处理建议 |
| --- | --- |
| 一次性标题、装饰背景、简单容器 | 留在页面层级，不为每个节点新建 Prefab 和脚本 |
| 同页重复的数据项 | 如奖励项、统计行，可独立 Item Prefab；明确数据绑定与复用重置 |
| 已被其他页面使用的稳定元素 | 优先复用现有公共 Widget，检查样式和参数能否满足 |
| 本页独立且复杂的交互区域 | 可拆本模块私有 Widget，页面负责组合和业务调度 |
| 仅推测将来会复用的区域 | 先保持局部实现，不为猜测建立公共组件或全局系统 |

新拆出的 Prefab 默认放所属模块；确认存在跨模块复用需求后才考虑公共域。纯视觉重复元素可以只有 Prefab，无须为了“组件化”附加空脚本。

### 1.5 一次确认关键制作决定

调查和分析完成后提供具体制作方案，再集中确认尚未决定的事项。方案至少包含：

```text
目标：页面用途、所属模块、本次交付范围
页面选择：修改哪个现有页 / 新增独立页，以及理由和受影响入口
结构：固定区、内容区、滚动区、操作区
复用：具体 Prefab/Widget、直接复用或修改的范围
新建：需要新做的 Item/Widget/素材
交互与数据：输入数据来源、按钮动作、业务负责方
未定事项：图片无法说明且会改变制作方案的问题
验收：如何对照效果图，以及如何从真实入口验证
```

只向用户询问真正影响结果的选择，一次优先 1–3 个问题。比如：

- “现有 GameOverUIPanel 会用于这些入口。你希望改版该页，还是新增独立结算页并保留原页？依据以上差异建议选择……。”
- “奖励数量是否会超过当前显示区域？建议标题和底部按钮固定，仅奖励区滚动。”
- “图中领取按钮是确认已有奖励，还是点击后才发放？由哪个现有业务接口处理？”

没有实质取舍时给出一个建议方案，不机械罗列多个方案；锚点、布局组件等常规实现细节由执行者按已确认目标处理。已有授权和用户明确指定的页面选择继续有效，不反复确认。

页面选择未确定时继续只读分析，不先覆盖旧页或分配新 UIForm ID；可以明确授予执行者按分析结果自行选择的权限。修改/新增本身不是统一的高风险门槛，按实际公共契约、资源移动和影响范围遵守项目边界。

### 1.6 按确认方案制作和接入

1. **布局与元素**：使用确认的页面/骨架；先搭分区、滚动和必要子 Prefab，用代表性数据检查视觉。占位素材和模拟数据必须可识别，不能当作业务已接通。
2. **脚本与绑定**：绑定显示字段和操作事件，页面接收本次数据，Widget 展示数据并报告交互；对已有页尊重原有业务契约，不借制作页面重构其他系统。
3. **注册与调用**：只有独立新增页面才分配新 ID；改已有页保留原身份并同步实际变化，新增 Widget 不登记 UIForm。按 §3 选择归属分支。
4. **分开验证视觉和功能**：视觉对照效果图检查结构/比例/文字/素材；功能从真实入口检查数据、交互、复用、退出清理。截图好看不能代替真实加载通过。

需要中途用户评审时，展示已形成的布局截图或明确结构草图及具体差异；不要每完成一个节点都停下来询问。已确认范围内连续完成制作和验证；出现会改变页面用途、业务契约或复用影响面的新信息时，再集中说明并确认。

### 1.7 结算页分析示例

以下是假设“顶部结果标题、中间统计/奖励、底部下一关按钮”的分析示例，不代表用户已经提供效果图或选择了此结构。

| 区域 | 初步建议 | 需要核实 |
| --- | --- | --- |
| 背景与标题 | 页面内普通节点，按模板配置动画和遮挡 | 全屏还是弹窗，失败状态是否共用页面 |
| 统计区 | 多行同构数据才拆 StatisticRow；固定少量文案可直接布局 | 字段来源、最大数字长度 |
| 奖励区 | 先检查现有 RewardItemView；不满足再做所属模块的 Item | 是否有宝箱、是否需要提示、奖励是否已经入账 |
| 可变内容区 | 内容可能溢出时局部滚动，按钮留在固定区域 | 最大数量、滚动方向、重开位置 |
| 操作区 | 按既有按钮视觉制作，调用确认过的业务动作 | 下一关、返回、重试、领取的真实语义与失败处理 |

新增页面可以复用已有奖励格子；修改旧页也可能需要新建一个统计行 Prefab。整页选择和元素复用应分别判断。

## 2. 新建前确定的配置

### 2.1 页面归属

| 类型 | 脚本 | Prefab | 额外注册 |
| --- | --- | --- | --- |
| 公共页 | `Assets/GameMain/Scripts/UI/Panel/` | `Assets/GameMain/UI/UIPanel/` | UIForm 表即可决定默认路径；仍需资源收集 |
| 子游戏页 | `Assets/GameMain/SubGame/{GameName}/Scripts/UI/` | `Assets/GameMain/SubGame/{GameName}/UI/` | 游戏自己的资源清单 + 全局清单引用 |
| 活动页 | `Assets/GameMain/Activities/{ActivityName}/Scripts/UI/` | `Assets/GameMain/Activities/{ActivityName}/UI/` | 活动 Definition 页面清单 + Catalog 安装 |

路径解析先查活动，再查子游戏，最后回落公共目录。资源名没有注册到正确域时，文件即使存在也可能被解析到公共目录。不要让不同域抢占同一个全局 AssetName；模块内 PageKey 与 UIForm AssetName 不是同一种键。

### 2.2 UIForm 表与 ID

源表：[UIForm.txt](../../../../GameMain/DataTables/UIForm.txt)。它是 **Tab 分隔**，保留四行表头及开头空列。

| 字段 | 含义 / 填写规则 |
| --- | --- |
| Id | 页面配置 ID；唯一正整数，与 `UIFormId.cs` 对应 |
| 策划备注 | 说明用途；参与生成枚举注释，不是资源路径 |
| AssetName | Prefab 逻辑资源名；也是工具生成枚举成员的依据，应使用合法 C# 名称 |
| UIGroupName | 必须等于 Launcher UIComponent 中真实存在的分组名 |
| AllowMultiInstance | `FALSE` 时，正在加载或已经打开的同资源页面不会再次打开 |
| PauseCoveredUIForm | 控制同组被覆盖页面的暂停行为；不自动暂停其他组或游戏逻辑 |

ID 分配依据 [UIFormIdRanges.cs](../../../../GameMain/Scripts/UI/Runtime/UIFormIdRanges.cs)：公共新增页 `100–199`；非活动共享/样例/子游戏区 `200–299`；活动从 `300` 起按独立 20 号区间分配。历史公共页面也有 `200` 段 ID，不要为整理分类重编号。具体活动区间查源码或 [活动接入 §6](../Activity/Integration.md#6-首页与多页面-ui)。

每次源表变更必须同步 `UIForm.bytes` 与 `UIFormId.cs`。`DRUIForm.cs` 是表结构代码，只有表结构变化才需要对应重新生成，不能靠手改它修正漏注册。

### 2.3 分组和覆盖

当前 Launcher 设置四组，名称与 [UIGroupType.cs](../../../../GameMain/Scripts/UI/Runtime/UIGroupType.cs) 对齐：

| 组名 | 深度 | 适用内容 |
| --- | --- | --- |
| Default | 0 | 普通页面、玩法主界面 |
| GamePlayOverlay | 1 | 游戏覆盖表现 |
| Dialog | 2 | 对话框、规则页、购买页 |
| SystemOverlay | 3 | 系统提示、Toast |

这是分组用途，不是所有旧页面的现有分类承诺；例如当前 SettingUIPanel 表行仍为 `Default`。核对表行，不根据页面名字推测组别。

`UGuiGroupHelper` 的组深度因子为 10000，`UGuiForm` 的组内深度因子为 100。框架会平移页面及子 Canvas 的排序值；子 Canvas 保持局部相对层级，不用极大的 sortingOrder 绕过分组。射线遮挡、页面暂停、玩法暂停分别配置和验证。

## 3. 添加页面与注册流程

本节从 §1 已确定页面选择和制作方案开始。先判断本次是否需要新注册：

| 本次操作 | 注册处理 |
| --- | --- |
| 修改现有页面的布局/绑定 | 保留原 UIForm ID 和资产身份；表字段/资源名未变化时无需仅因改布局重生成表 |
| 新增独立页面 | 按下面的公共/子游戏/活动分支创建和注册 |
| 新增页面内部 Widget / 列表项 | 不增加 UIForm 行或 ID；由所属页面加载/引用和管理 |

修改已有页面前，定位真实 Prefab、脚本、表行和调用方。已有页面的参数或行为要变化时，先说明调用方影响；不能用“制作结算页”为由替换其他游戏仍在使用的逻辑。

### 3.1 公共页面

1. 确认是新增公共页，且工具的公共目录和 `UIPanel_Template` 满足已确认方案，再打开 `Tools/UI/UI Panel Manager`。输入页面名、备注、分组和覆盖暂停选项；工具会补 `UIPanel` 后缀并将首字母大写。
2. 勾选 `Create / Update Prefab` 后执行添加。工具在公共范围分配空闲 ID，写源表、生成 bytes/枚举、创建脚本；编译重载后创建或更新 Prefab。
3. 新 Prefab 来自 [UIPanel_Template.prefab](../../../../GameMain/UI/Template/UIPanel_Template.prefab)。模板缺失时仅生成最小根节点，不能当作已完成视觉和交互。
4. 等待编译完成，进入 Prefab Mode 制作内容，检查根节点页面脚本与所有序列化引用。更新已有 Prefab 可能替换根 UGuiForm 组件，操作后应读回绑定。
5. 工具新增行默认禁止多实例。需要多实例或后续修改表行时，编辑源表，再执行 `Tools/UI/Sync UIForm Registration`；窗口中的 `Sync UIFormId` 也会同步表、bytes 和枚举。
6. 核对资源收集，从实际入口调用并完成[页面交付验收](Validation.md)。

工具关闭 `Create / Update Prefab` 只跳过 Prefab，并不会改成子游戏/活动模式：脚本仍创建在公共目录。工具的 Delete 会删除注册及公共位置的脚本/Prefab，不是“从列表隐藏”；已有资源移除按项目高风险与备份规则执行。

若用户提供了设计好的 Prefab 或选定另一骨架，应保留其结构，通过已有 Unity 操作绑定脚本并维护表源，再用同步入口生成注册；不要为了走生成工具覆盖设计师资产。模板缺失时也不能把最小根节点交付为已还原效果图的页面。

### 3.2 子游戏页面

1. 在所属游戏 `Scripts/UI/` 创建 `Lokas` 命名空间下的 UGuiForm 派生脚本，在该游戏 `UI/` 制作 Prefab；不要先生成公共页再留在公共目录。
2. 在 `UIForm.txt` 添加未占用的子游戏区 ID、AssetName、分组和两个行为开关；执行 `Tools/UI/Sync UIForm Registration` 同步生成物。
3. 用 `Tools/SubGame/Asset Registry Config` 把 AssetName 登记到该游戏资源清单。确认全局 `SubGameAssetRegistryConfig.asset` 的 `m_Manifests` 包含该清单。
4. 核对清单的启动元数据收集与 Prefab 的资源收集；表注册、资源域注册和构建收集是三个环节。
5. 由所属 Procedure/业务入口打开；退出游戏关闭页面并使未完成请求失效。详细流程见 [子游戏模块](../SubGame/Extensions.md)。

### 3.3 活动页面

1. 在活动自己的 `Scripts/UI/` 和 `UI/` 制作脚本与 Prefab，参数类型由活动拥有。
2. 在活动 Definition 的页面清单登记 **PageKey、UIForm ID、AssetName、模块内 Prefab 路径**，ID 位于该活动区间。
3. 确认 Definition 已被全局 ActivityModuleCatalog 引用。通过该活动已有安装入口同步页面表、bytes、ID，并检查安装器输出；安装器不是通用设计师 Prefab 生成器。
4. 预加载安装 Catalog 后，ActivityPageRegistry 才能提供路径。业务从宿主入口或 `context.UI.OpenAsync(...)` 开页，保留 ModuleId/Generation/SerialId 的作用域。
5. 按 [活动接入 §6](../Activity/Integration.md#6-首页与多页面-ui) 验证取消、停用及关闭；通行证还需满足 [专用 Prefab 契约](../../../../GameMain/Activities/SeasonPass/Docs/UIPrefabContract.md)。

仅注册 UIForm 表不会自动把页面加入活动模块；绕过活动上下文直接开页也不等于拥有活动的实例清理保障。
