## 1. 字符集与 SDF 更新流程

### 1.1 确定字符来源

| 字符集文件 | 对应内容 |
| --- | --- |
| unity_sdf_charset.txt | MFont_BASE 所需的公共字符；按实际语言映射检查拉丁字符、数字、符号等 |
| unity_sdf_charset_CNS.txt / CNT.txt | 简体 / 繁体中文 |
| unity_sdf_charset_JP.txt / KR.txt | 日文 / 韩文 |
| unity_sdf_charset_Arabic.txt / Hindi.txt / Thai.txt | 对应书写系统的字符输入；文件存在不代表语言已上线 |

上述文件位于 [Charset](../../../Fonts/Charset)。启动加载视图还拥有 [unity_sdf_charset_loading.txt](../../../../GameMain/CustomComponents/BuiltinView/Font/unity_sdf_charset_loading.txt)，改加载页文字时独立检查，不能只更新普通 UI 的字库。

收集解析后的显示文本，同时覆盖数字、标点、百分号、计时单位、格式化结果和手工动态字符串。富文本标签本身通常不是可见字形；保留原有字符并追加本次缺口，不只用单页文本重建整个共享字库。没有有限字符集合的玩家输入等内容，需要另行明确覆盖策略，不能用翻译表字符集承诺覆盖一切。

### 1.2 统一更新工具：日常操作

入口为 **Game Framework → 字体与字符集 → 打开窗口**。已有 [四语言配置](../../../Fonts/Editor/FontCharsetConfig.asset)；首次接入其他工程时才使用“创建默认配置”。工具仅在编辑态更新当前选中语言，默认包含 CNS / CNT / JP / KR，不更新 MFont_BASE。

日常只需在 **更新字符集** 页勾选语言 → **检查选中语言** → **更新字符集与图集**。全选四种语言即可统一更新，无需逐项修改参数。首次打开显示“未检查”，不会把旧报告当作当前检查结果。

1. **选择并检查**：先保存 XML 文案，再勾选简中、繁中、日语、韩语中的目标语言。首页每行只显示字体与简短状态，点击“详情”才展开新增字符、图集缺字或错误来源。检查不写项目资产；检查通过且存在变化时，才启用更新按钮。
2. **必要时设置字体**：通过该语言行的“设置”进入 **字体设置** 页，每次只显示一种语言。源字体和补充文字直接可见；图集参数、文字来源与文件映射、项目配置分别折叠。容量不足时从该行进入设置，自动展开图集参数。初始源字体从现有字体创建记录恢复，不凭文件名猜测。
3. **补充动态内容**：“补充文字”按字面收集，默认包含数字及常用格式符号。`{0}` 不能推导动态字符串，活动名称、计时输出等需提供实际可能出现的字符。新增 XML 文件加入“文字来源与文件映射”的列表，不自动扫描脚本或 Prefab 字符串。改设置后点击“保存设置并去检查”。
4. **统一更新**：工具重新扫描后，自动保存本次涉及的字体、材质及当前制作配置，无需手动寻找保存入口。全部语言的临时图集生成成功后，备份已保存状态，再同步 TXT 与原字体。已有字符只追加不删减；未变化项跳过。更换源字体会重建字形，需检查字宽和页面换行。
5. **检查结果**：首页显示“已同步”；在 **预览** 页选择语言并输入文字，查看已保存字体与默认材质。预览不替代运行时 Profile 样式、fallback、页面排版或目标平台资源加载验收。

采样字号提供“自动大小 (Auto Sizing)”与“自定义 (Custom Size)”，默认自动。自动模式在固定图集内按实际字形装箱结果、以 1–512 为范围搜索可容纳全部字符的字号；更新详情显示实际生成字号。自定义模式保持输入字号，放不下则报错。图集宽高分别下拉选择 8、16、32、64、128、256、512、1024、2048、4096、8192，工具不自动扩容；Padding 须小于图集短边的一半。

首版只更新已有的单图集 Static 字体，Atlas 和默认材质须为目标字体内嵌子资产。生成阶段使用临时字体，写回后保持 Static，不能据此宣称已启用运行时补字。自动采样改变的是图集中的字形采样字号，不会修改页面 TMP_Text 的显示字号；字符变多时采样字号可能下降，需要检查清晰度。

字符输入为：**已有 TXT ∪ 字体已有字符 ∪ 对应语言 XML 可见文字 ∪ 手工补充文字**。按 Unicode 码点去重，保留普通空格和可见标点，忽略换行等控制字符。解析 XML 转义、常见 TMP 标签、`noparse`、格式占位符及转义花括号；大小写标签保守加入转换后的字符。未知标签按字面保留；会展开额外文字的 `<style>` 明确报错，需先提供展开后的内容，不能静默漏字。

### 1.3 失败处理、备份与自动化入口

| 结果 | 处理 |
| --- | --- |
| 源字体缺字 | 根据码点与来源 Key 核对文本或源字体，单纯扩大图集无效 |
| 图集容量不足 | 自定义模式可切换自动大小，或调整图集尺寸/Padding；自动模式在搜索范围内仍无法容纳时停止，不自行扩容或换字体 |
| 取消生成 | 取消在保存前、语言之间、自动字号试算之间及写回前检查；单个原生生成调用结束后响应。生成结果未写入，已经自动保存的原有编辑会保留 |
| 资产有未保存修改 | 点击更新后自动保存本批次涉及的字体、材质、子资产及制作配置，再继续生成；不调用全项目 SaveAssets。异常情况下保存后仍存在未保存修改，会提供“重试更新”入口 |
| 文件只读 | 先解除目标文件只读状态，再检查和更新 |
| 写入中断 | 本批次从备份恢复；若编辑器退出留下未完成事务，先执行“恢复未完成更新” |

备份位于项目根 `Backups/FontCharset/<时间与标识>/`，包含本批次字体、字符集、受影响材质、制作配置及其 meta，并保留清单。保留主资产和子资产 GUID/fileID，不删除重建字体；同步引用图集的材质尺寸及 GradientScale，保留配色、描边、阴影等样式参数与 fallback。发生恢复失败时保留事务记录和备份，停止后续更新。

人工窗口与自动化共用 [FontCharsetService](../../../Editor/FontCharset/FontCharsetService.cs)。AI 可以调用以下真实菜单：

- `Game Framework/字体与字符集/扫描全部`：读取默认配置，只扫描，写入本机诊断报告。
- `Game Framework/字体与字符集/更新选中语言`：使用当前加载配置中的选中项；与窗口共用自动保存与更新流程。报告的 `savedAssetPaths` 列出本次自动保存的资产。后续取消或回滚仍保留这些原有编辑。
- `Game Framework/字体与字符集/恢复未完成更新`：恢复尚未完成的写入。
- `Game Framework/字体与字符集/运行工具验证`：在临时副本上验证解析、取消、容量/源字体缺字、回滚、保留引用及重复执行；不更新正式字体。

报告在 `Library/FontCharset/last-report.json`，每次覆盖。检查 `success`、`message`、每行 `status` 和 `backupPath`，不能把“菜单执行成功”当成“图集生成成功”。纯扫描不会验证图集能否装下全部字形；更新时的临时生成才会验证容量。工具测试记录位于 `Library/FontCharset/validation.txt`。

修改源字体、图集或字符集后，在发布前重新构建相关资源；工具不会自动执行整个资源构建或修改语言启用名单。Unity 不可用时可以分析字符需求，但不能报告图集已同步。个人 `localization-sdf-charset` 技能优先使用本工具；旧 Python 脚本仅作为明确授权的 TXT 辅助更新，不能代替图集生成。

### 1.4 手工 Font Asset Creator 流程

不使用统一工具时，按以下步骤操作；手工改动后再次使用工具，需确认制作配置与当前资产参数一致。

1. 明确目标 SDF、已有源字体、创建参数、使用语言及引用范围；不要按资产名字猜测源字体。
2. 比较需求字符和已有字符集/SDF 覆盖，输出本次缺字与会更新的资产。
3. 更新对应字符集，保持已有字符；文件统一保持可读 Unicode 文本。
4. 在 Font Asset Creator 选择正确源字体，Character Set 使用 `Characters from File` 读取目标字符集；根据既有参数生成，并检查缺字/未打包字符结果。
5. 更新已有字体时在 Unity 中保留资产身份与引用，核对字体资产、Atlas、材质及 fallback；不删除重建 `.meta`。新增字体保存到已确定运行时路径并更新 LanguageEntry/资源收集。
6. 检查描述性的长文本、描边/阴影边界、图集清晰度、Mask 裁切及真实页面，最后验证目标构建的加载路径。

当前核对的 MFont_BASE、MFont_JP 为 Static 图集。即使 Multi Atlas 开关开启，也不能当作运行时自动补字已经启用；不能只修改 charset 就认为页面已修复。源字体缺少字符与图集容纳不下字符应分别处理，不盲目增大 Atlas。

若考虑切换 Dynamic 模式，需要另行评估源字体可用性、覆盖和资源代价，不把它作为文档整理或单次补字的默认修改。复杂书写系统除字符覆盖外，还需实际排版验证。
