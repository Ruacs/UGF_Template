# Galaxy Challenge

`GalaxyChallenge` 对应 Hexa Away 的 `OutGame.StageChain` / `hexachase` 活动。

## 页面

| PageKey | UIForm | 用途 |
| --- | --- | --- |
| `start` | `GalaxyChallengeStartUIPanel` | 首次进入与加入活动 |
| `main` | `GalaxyChallengeMainUIPanel` | 固定 5/7 步挑战棋盘 |
| `details` | `GalaxyChallengeDetailUIPanel` | 三段玩法说明 |
| `end` | `GalaxyChallengeEndUIPanel` | 本轮完成摘要 |
| `interval` | `GalaxyChallengeIntervalUIPanel` | 失败、关闭或领奖后的等待状态 |

页面 Prefab 位于 `UI/`，专用脚本位于 `Scripts/UI/`。所有可见节点、Sprite、锚点、尺寸和层级均由
Prefab 维护；运行时代码只刷新文本、按钮状态和已经序列化的状态节点，不创建 UI、不补组件，也不修改
`RectTransform` 做屏幕适配。

## 玩家头像演出

- 活动规则始终按 100 名逻辑玩家结算；主页面使用 24 个预置的 `AvatarBox.prefab` 头像表现位，避免同时
  渲染 100 个完整头像。24 个头像按前、中、后三层重叠排布，`CanvasGroup`、头像层和每一步的落点都已经在主页面 Prefab 中配置并绑定。
- 5 步模式使用“起点 + 5 个关卡平台”，7 步模式使用“起点 + 7 个关卡平台”。页面只启用与当前活动
  步数匹配的完整布局，不在代码中生成、重排或适配平台。
- 完成一关后，当前可见头像会依次跳到下一平台；随后按该步逻辑存活人数缩减表现头像，多余头像执行
  下落、旋转、淡出并隐藏。NPC 头像和头像框均按本轮种子从 AvatarDatabase 配置中选择；失败时玩家头像
  也会随同一段跳跃演出落下并被淘汰。
- 胜利 Overlay 预置 6 个 NPC 获胜者表现位，但显示数量按本轮最终存活人数动态裁剪（玩家头像单独占 1 位），
  因此不会固定显示 6 人；头像框尺寸与主平台上的 AvatarLayer 紧凑布局均由主页面 Prefab 维护。
- 进度与“已播放到第几步”分别持久化。若结算后关闭页面或最后一关直接完成，下次进入主页面仍会先补播
  尚未确认的跳跃/淘汰演出，再进入最终状态。
- 5 步模式采用导出样本中的 `100 → 40 → 18 → 12 → 8 → 6~7`；7 步模式按配置的衰减曲线生成严格
  递减人数，并保证最终落在文档要求的 `4~6` 人范围。最终人数由本轮种子确定，同一轮重开页面不会变化。

头像的 `RectTransform` 仅在运行时用于跳跃和淘汰动画，不承担 UI 布局或屏幕适配职责。

## 测试模式

编辑器或 Development Build 中，活动初始化后会向现有 TestMode 注册 `Galaxy Challenge / Progress`
页面，活动停用时自动注销。测试页提供：

- 在 Event 2（5 步）和 Event 1（7 步）之间切换；应用模式时会重置本地活动状态。
- 打开主页面、加入活动或清除失败等待时间。
- 一次模拟 1–7 次胜利，用于连续观察头像跳跃、淘汰和最终人数。
- 模拟失败，以及重置当前模式的数据。
- 实时显示活动状态、逻辑存活人数、当前进度和已播放到的进度。

测试模式只驱动活动状态并复用正式主页面，不创建另一套 Galaxy Challenge UI。

## 配置基线

- Event 1：7 步、间隔 1800 秒、100 人、奖池 10000、预计全清率 4%–6%。
- Event 2：5 步、间隔 1800 秒、100 人、奖池 10000、预计全清率 6%–7%。
- 每个活动窗口为 10 小时；失败、关闭当前轮次或领取胜利奖励后等待 30 分钟再开始下一轮。
- 解锁等级：40。
- 周期：周五 00:00 至周日 23:59:59（活动模块按 UTC 周期判断；Editor 可保持开启便于验收）。

通关后主页面显示胜利 Overlay，按最终存活人数平分金币奖池；领取成功后进入 30 分钟间隔。
